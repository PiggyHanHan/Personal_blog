# 私有文章加密（往生堂门扉）

> 给开发者的实现说明。使用者视角的写法见 `docs/user/内容更新指南.md` 的「私有文章」一节。

## 一、要做的事

给文章 frontmatter 加一行 `private: true`，这篇的**正文**在构建时被 AES-256 加密后随静态页面下发；
读者在详情页看到的是往生堂门扉，输入口令后浏览器本地解密、渲染全文。
标题 / 日期 / 分类 / 摘要 / 标签仍是明文（列表页、搜索、上下篇导航照常工作）。

## 二、数据流

```
content/posts/xxx.md  (private: true)
        │  gray-matter 解析
        ▼
   markdownToBlocks()  →  Block[]
        │  renderToStaticMarkup(<PostBody blocks>)      ← 与详情页正文同一条渲染路径
        ▼
      HTML 字符串
        │  PBKDF2-SHA256(口令, 随机盐, 250000 次) → 32B 密钥
        │  AES-256-GCM(密钥, 随机 IV=12B)
        ▼
  PrivatePayload { v, kdf, iter, cipher, salt, iv, ct }   ← 只有密文，没有口令、没有密钥
        │  随静态 HTML / RSC 载荷下发
        ▼
  浏览器 PrivateGate：读者输入口令 → WebCrypto 现推密钥 → 解密 → dangerouslySetInnerHTML
```

关键点：**口令只在构建机上，产物里没有口令也没有密钥**。攻击者拿到网页全部内容（含密文）也无法在不知道口令的情况下解密；口令错误或密文被篡改时 GCM 认证标签校验直接失败，不会渲染出乱码。

## 三、代码分布

| 文件 | 职责 |
|---|---|
| `lib/privateCrypto.ts` | 载荷类型 + 算法参数 + base64 互转 + 口令 NFKC 归一化（**同构**，浏览器也要用，不 import `node:*`） |
| `lib/privateContent.ts` | 构建期加密：`blocksToHtml()`、`encryptHtml()`、`isEncryptSkipped()`、`privatePassword()`（服务端专用） |
| `lib/postHtml.ts` | `Block[] → HTML`（与 `PostBody.tsx` 同构，详见第九节的不变式） |
| `lib/posts.ts` | 识别 `private`、决定加密还是明文、把结果塞进 `Post.encrypted` |
| `components/post/PrivateGate.tsx` | 客户端门扉：锁屏（场景 + 门扉 + 横线口令框 + 神之眼）、WebCrypto 解密、开门动画、会话记忆 |
| `components/ui/FireVision.tsx` | 火系神之眼单元（开屏与门扉共用：脉动光晕 + 点亮后的火元素外溢） |
| `components/ui/Sigil.tsx` | 主题纹章（公开＝胡桃的安魂 / 私有＝七七蓝魂魄） |
| `components/layout/IntroOverlay.tsx` | 开屏动画；门扉复用的就是它的虚化背景、Q版胡桃、神之眼与收窗帘 |
| `app/posts/[slug]/page.tsx` | 有密文就渲染门扉，没有（本地预览）就明文渲染 + 提示条 |
| `app/blog.css` | 文末「私有内容」一节：纹章、徽章、锁屏、开门动画 |

## 四、算法参数

| 项 | 值 | 说明 |
|---|---|---|
| KDF | PBKDF2-HMAC-SHA256 | 迭代次数 **250000**，写进载荷的 `iter` 字段 |
| 盐 | 16 字节随机，每篇独立 | 同一口令在不同文章推不出相同密钥 |
| 加密 | AES-256-GCM | 认证加密；载荷 `ct` = 密文 ‖ 16 字节认证标签（WebCrypto 的格式） |
| IV | 12 字节随机，每篇独立 | GCM 标准长度 |
| 口令归一化 | `String.prototype.normalize("NFKC")` | 两端必须一致：中文输入法打出的全角字符也能和半角对上 |

调参只改 `lib/privateCrypto.ts` 里的 `PRIVATE_ITERATIONS`；旧文章解密用的是**载荷里记的** `iter`，所以改参数不会让已发布的文章打不开（重新构建后才会用新参数重加密）。

## 五、口令从哪来

- 构建机：项目根目录 `.env.local` 里的 `PRIVATE_POST_PASSWORD`（`.gitignore` 的 `.env*` 已忽略，不进 Git）。
- 服务器：`/var/www/blog/.env.local` 放**同一份**（`deploy-code.ps1` 只删代码目录、不删 `.env.local`）。
- **两边必须一致**，改口令/首次配置都走 `usertools\set-private-password.ps1`（场景五）：改本地 → base64 临时文件 scp → 远端替换那一行 → 服务器 `npm run build && pm2 restart blog`。口令不出现在 ssh 命令行，也不进远端 shell 历史；`-Generate` 直接给一个 20 位随机串。
- 缺口令时有私有文章 → **构建直接失败并报错**，绝不静默降级成明文（这是刻意的防泄露设计）。

模板见仓库根目录 `.env.example`。

## 六、本地预览 vs 生产

| | 本地写作预览 | 生产 |
|---|---|---|
| 入口 | `usertools\local-run.ps1` | `usertools\sync-content.ps1` / `deploy-code.ps1` |
| 环境变量 | `SKIP_ENCRYPT=true`（脚本自动设） | 不设 |
| 结果 | 私有文章**明文**，正文全文可见、无需口令 | 私有文章加密，详情页是往生堂门扉 |
| 卡片外观 | 仍然带 🔒 徽章与七七纹章（只是视觉标记） | 同左 |
| 提醒 | 构建时终端打警告 + 详情页顶部一条提示条 | 无 |

想在本机验证真实加密链路（门扉 / 口令 / 解密）：

```powershell
usertools\local-run.ps1 -Encrypt     # 不设 SKIP_ENCRYPT，走与生产一致的加密路径
```

> ⚠ `SKIP_ENCRYPT=true` 的产物**是明文的**，不要把它挂到公网（包括本机起服务 + Cloudflare 隧道这种用法）。

## 七、主题视觉

| 场景 | 图案 |
|---|---|
| 公开文章卡片 / 项目卡片 / 友链卡片 | 胡桃的安魂（`public/theme/hutao-requiem.webp`） |
| 私有内容卡片 | 七七的蓝色魂魄（`public/theme/qiqi-soul.webp`）+ 🔒 徽章 |
| 私有文章锁屏 | 往生堂门扉（`public/theme/wangsheng-door.webp`，**透明底，直接浮在场景上，不加底衬**） |

**纹章骑在卡片右下角**：`position: absolute`，桌面 5.5rem（友链 4.5rem）、约 1/3 压在卡片内、2/3 探到卡片外
（横向伸出 24px 正好用掉 `main` 的左右内边距，不会顶出视口；纵向伸出 54px 落进卡片间距里，
所以 `.quest-board` / `.project-list` 的 `gap` 提到 3.6rem、友链 3rem——**改纹章尺寸或偏移时要同步改这几处 gap**，
否则纹章会压到下一张卡片）。≤640px 一档整体缩小并向内收。

素材放在 **`public/theme/`**：`public/hutao/` 被 `.gitignore` 忽略、也不在 `deploy-light.ps1` 的打包清单里（那目录是给大体量背景 / 音频用的），纹章和门扉是界面必需资源，必须跟着 Git 和部署包走。

## 八、锁屏（往生堂门扉）的形态

锁屏不是"夹在文章卡片里的一块"，而是**整屏接管**，直接复用开屏（IntroOverlay）那一套素材与动画：

| 环节 | 复用来源 |
|---|---|
| 背景 | 开屏第二屏那套：`useBg()` 的博客背景当前图 + `.intro-white-bg`（blur 30px / brightness 1.8）+ `.intro-white-tint`，**同一组样式类**，改开屏背景观感会同时改到锁屏 |
| 门扉 | 透明底 `wangsheng-door.webp`，居中靠上浮在虚化背景上（**不加底衬**） |
| 叩门 | 下半屏一条横线口令框（无底、无边框），右侧一枚火系神之眼当按钮（`FireVision`） |
| 叩对 | 火元素纹样外溢闪烁 →（见下方三拍节奏）→ Q版胡桃 `chibi2.png` + `起！`/`energy-full`（`useIntroSounds`） |
| 进门 | 与开屏同一个"收窗帘"（`clip-path` 自下而上 + `.intro-curtain-edge` 收拢边上推），卷完直接落在正文上 |

**开门三拍（不许抢拍，与开屏的先后关系一致）**，都在 `PrivateGate` 的 `opening` 阶段里按序 await：

1. **门扉先整张淡出**（`DOOR_FADE_MS = 900`，与开屏 `FADE_MS` 相同）——门没走完不许出现胡桃；
2. 门走完了 **Q版胡桃才登场**，同时放 `起！` + `energy-full`；
3. **等 `起！` 放完**（`useIntroSounds` 新增的 `playAndWait`：听 `ended` 事件，音频缺失/被拦截/时长未知按 `BURST_FALLBACK_MS = 1600` 兜底）**才卷门帘**——否则门帘会在底部先"啪"地露出一排边，很难看（`.post-gate__curtain` 另外加了 0.3s 淡入）。

- 锁屏盖住整屏（`z-index: 9000`）：窄屏时 `.sidebar` 会变成 `z-index: 100` 的顶部横条，必须压过它；但仍低于开屏（9999）与设置齿轮（10000）。
- **口令错误 = 界面完全无反应**（不抖动、不报错、不提示），只往 `role="status"` 的读屏区写一句"门没有动。"。这是刻意的表现要求——要不要给可见反馈属于产品选择，改的话在 `PrivateGate` 的 catch 分支里加。
- 锁屏只有一行文字（口令框的 placeholder），**没有单独的文章提示语**（曾经支持过 frontmatter `privateHint`，已按需求移除）。
- 锁屏左上角留了一条"← 返回文章列表"（不想输口令也有退路）。
- 会话里已有口令时（同一次浏览的第二篇私有文章）**不再走开门动画**，直接进正文；只有读者亲手叩门才播。
- 「重新上锁」= 清掉会话口令 + 回到文章卡片界面（`/posts?post=<slug>`，复用既有的"返回定位到本篇卡片"逻辑）。

## 九、扩展到项目 / 友链

`content/projects.json` 的项目对象与 `content/links.json` 的友链对象都支持 `"private": true`：
卡片换成七七纹章并显示 🔒 私有徽章。它只改**视觉标记**，不隐藏内容、也不加密——用在不方便公开的条目上做提示。
（真正需要"内容不可见"的东西，请用文章 + `private: true`。）

## 十、验证

```powershell
npm.cmd run build                                # 生产构建（加密）
node scripts\verify-private-crypto.mjs           # 端到端校验（见下）
```

`scripts/verify-private-crypto.mjs` 做三件事：

1. 从 `.next/` 里找出每篇私有文章的实际载荷（正则抽取页面里下发的密文）；
2. 用 Node 的 WebCrypto（与浏览器同一套 `crypto.subtle` API、同样的 PBKDF2/AES-GCM 参数）用 `.env.local` 的口令解密，断言解出来的 HTML 与源 Markdown 一致；
3. 扫 `.next/` 全部文件，断言正文里的原文**一句都没有**以明文出现（防止密文旁边漏出明文副本）。

## 十一、已知边界（有意为之）

- **只保护正文**：标题 / 日期 / 分类 / 摘要 / 标签是明文（列表页要用）。摘要别写敏感信息。
- **正文里的插图不加密**：图片走 `public/md_images/` 的公开 URL，知道路径就能直接打开。敏感图别放正文。
- **附件 PDF 不加密**：`/files/` 由 Nginx 直接托管。私有文章若带 `pdf` 字段，PDF 本身仍可被直链访问（详情页里它会被放进"门后"，但那只挡住页面入口）。真要保密，把 PDF 也换成加密文章正文。
- **不是服务端鉴权**：明文只存在于读者的浏览器内存里；口令在叩门成功后**总是**存进 `sessionStorage`（关标签页失效），同一标签页里其它私有文章直接开门（不再走动画）。共享电脑上点「重新上锁」（会清掉口令并回到卡片列表）。
- **需要 HTTPS 或 localhost**：`crypto.subtle` 只在安全上下文可用；用 `http://192.168.x.x` 访问会显示提示而无法解密。
- **需要 JavaScript**：静态站没有服务端解密，禁用 JS 只能看到门扉。
- **锁屏依赖开屏素材**：虚化背景用的是 `public/bg/` 的博客背景图，Q版胡桃 / 神之眼在 `public/hutao/`（两者都不跟 Git 走）。素材缺失时：神之眼退化成 🔥 文字按钮、Q版胡桃跳过、背景退化成纸色底，门扉（`public/theme/`，跟 Git）始终在。`起！` 音效缺失或被浏览器拦截时按 1.6s 兜底继续开门（不会卡住）。
- **口令强度就是全部安全性**：密文是公开的，任何人都可以离线爆破。用 12 位以上随机串；站点若改口令，重新构建即可，旧密文会被新口令重加密。
