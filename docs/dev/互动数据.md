# 互动数据（访客计数 / 点赞 / 多表情反应）

> 相关文件：`lib/db.ts`、`lib/analytics.ts`、`lib/reactions.ts`、`lib/postIndex.ts`、
> `lib/reactionStore.ts`、`lib/visitStore.ts`、`app/api/stats/route.ts`、`app/api/like/route.ts`、
> `components/interaction/*`、`scripts/gen-post-index.mjs`、`usertools/nginx-blog.conf`。

## 一、决策：为什么是 `node:sqlite`

三选一里选它，依据是**实测**而不是偏好：

| 方案 | 结论 | 依据 |
|---|---|---|
| **`node:sqlite`（选定）** | ✅ 开箱可用 | Node ≥ 22.13 时 `require("node:sqlite")` 不需要任何 flag（只打印一条 ExperimentalWarning）；Node 22.5 以下没有这个模块 |
| `better-sqlite3` | ❌ 不必要 | 要 node-gyp 原生编译、要进部署包，服务器每次 `npm install` 都有编译失败风险；功能上并不比内置的多 |
| 纯 JSON + 原子写 | ❌ 风险更高 | 要自己实现"读-改-写 + 临时文件改名"才能防写坏，并发下仍要靠进程内锁；SQLite 的 WAL 是现成的 |

**配套事实**：数据在磁盘上，`pm2 restart` 清空内存也不影响计数。

## 二、数据放哪、为什么

```
data/blog.db            ← SQLite（本地与服务器各一份，互不同步）
data/post-index.json    ← 构建期生成的文章清单
```

- `data/` **不在** `usertools/deploy-light.ps1` 的白名单里 → 本地打包不会带空目录上去覆盖线上数据；
- `data/` **不在** `usertools/deploy-code.ps1` 的 `rm -rf` 列表里 → 代码更新不会删掉互动数据；
- `.gitignore` 里有 `/data/`。

表结构（`lib/db.ts` 的 `SCHEMA`，**真实 SQL 只有这一处**）：

- `meta(k, v)`：运行期元数据，目前只有 `visitor_salt`（首次运行随机生成并落库，**不进 Git、不下发浏览器**）；
- `visits(id, ts, day, path, slug, visitor, ua)`：一次页面浏览一行（PV）；`visitor` = `sha256(ip + ua + salt + 当天)` 前 32 位，**IP 本身绝不落库**；
- `reactions(slug, kind, visitor, ts)`：主键 `(slug, kind, visitor)`，天然保证"同一访客同一表情只算一次"。

## 三、请求链路

```
浏览器                                          服务器
────────────────────────────────────────────────────────────────
VisitReporter（挂在 layout，只上报不显示）        POST /api/stats  { path }
  每次路由变化上报一次 ───────────────────────▶   · path 白名单化（站内绝对路径，≤300 字符）
  数字由开屏 + 侧边栏 + 单篇阅读数共享显示           · slug 由**服务端**从 /posts/<slug> 推导 + 清单校验
  （lib/visitStore.ts 单例，静态 HTML 里没有计数）    · 同一 visitor + 同一 path 10 秒内去重
                                                  · 落盘 → 返回 { today:{visitors,views}, total:{...}, isNewToday, posts: { slug: PV } }
                                                GET  /api/stats（只读）

CardLikes（每张卡片）／ReactionBar（详情页）
  useSyncExternalStore ◀── 全站**只发一次** GET /api/like ──▶ 全部 slug 的计数 + "我点过哪些"
  点击 → 乐观更新 → POST /api/like { slug, kind } ─────────▶ 切换（再点一次取消）→ 回传权威计数
```

**为什么 `/posts` 还能保持静态（○）**：页面组件一个数字都不碰，全部由客户端 hydrate 后拉取。构建产物里的 `/posts` 是纯静态 HTML，`/api/stats`、`/api/like` 是 ƒ 动态。

**为什么卡片只发一个请求**：计数放在 `lib/reactionStore.ts` 的模块级单例里（订阅式外部状态），10 张卡片共享同一份快照；模块级状态在 SPA 导航之间不丢，切页面不重复拉。
用 `useSyncExternalStore` 而不是 Context，是因为 `QuestCard` 既在服务端页面组件里渲染、也在客户端搜索结果里渲染，套 Provider 反而更麻烦。

## 四、四个数的口径

| 字段 | 含义 | SQL |
|---|---|---|
| `today.visitors` | 今日来访旅人（按天去重；当前这位已计入） | `COUNT(DISTINCT visitor) WHERE day = 今天` |
| `today.views` | 今日翻阅次数 | `COUNT(*) WHERE day = 今天` |
| `total.visitors` | 历史来访旅人 —— **累计「访客·天数」** | `COUNT(DISTINCT visitor)` |
| `total.views` | 历史翻阅次数 | `COUNT(*)` |

⚠️ `total.visitors` **不是"独立人数"**：visitor 哈希里带了日期（刻意不做长期跟踪），所以同一个人换一天会各算一位。这一点写在悬浮提示里（`VISITS.hint`），别把它当成 UV 人数去宣传。

展示分工（`components/interaction/VisitorLine.tsx` 一个组件两种 variant）：
开屏只留「你是今日第 N 位旅人」（**小数字才有社交气息**，历史累计动辄几百，放这儿反而生分）；
侧边栏四行写全：同一句 + 今日翻阅次数 + 历史来访旅人 + 历史翻阅次数。

## 五、单篇阅读数（`posts` 映射）

`lib/analytics.ts` 的 `publicViewCounts()` 从 `visits.slug` 聚合出**每篇公开文章的 PV**，
随 `/api/stats` 的响应一起下发（`posts: { slug: 数字 }`）：

```
GET/POST /api/stats ─▶ { …, posts: { "hello-world": 12 } }
        │
        └─ lib/visitStore.ts 的同一份快照（posts 字段）
             ├─ usePostViewCount(slug)  ← null 表示"没有这个数"（没数据 / 0 / 私有文章）
             └─ components/interaction/ViewCount.tsx（只读徽章，两处：标题下 + 文末互动条）
```

三条口径**不要改**（改了就是数据事故）：

1. **这是 PV 不是 UV**：同一个人多次打开会重复计数（同路径 10 秒内去重）。
   文案只写「翻阅 N 次」。要"多少人看过"得另出 `COUNT(DISTINCT visitor) WHERE slug = ?`，**两种数不许混着显示**。
2. **零值不显示**：没被翻开过的篇目服务端不会给它建 key，客户端拿不到就**整块不渲染**
   （显示 `0` 等于说"这篇没人看过"，还会让人以为数据坏了）。
3. **私有文章绝不显示**：`publicViewCounts()` 用 `getPublicSlugs()` 过滤，私有文章的浏览照常记录，
   但**不进公开映射**。所以锁屏、错口令、**解锁之后**都不该出现这个数字。

**为什么不再多发一个请求**：`posts` 搭的是 `VisitReporter` 那次 `POST /api/stats` 的顺风车
（同一份快照给旅人簿和阅读数共用）。全站仍然只有一次 stats + 一次 like —— 这一点在
`scripts/verify-view-counts.mjs` 里是**当断言跑的**（`stats=1 like=1`）。

端到端校验：`node scripts/verify-view-counts.mjs`（真浏览器跑，跑完自动清理测试数据）。

## 六、slug 白名单 = 构建期静态清单

互动接口**绝不能**调 `getAllPosts()`：那会触发全量 Markdown 解析，每篇私有文章还要现跑一次 25 万次 PBKDF2
（单次约 4 秒，见 `docs/dev/私有文章加密.md`）。所以：

```
npm run prebuild ─▶ scripts/gen-post-index.mjs ─▶ data/post-index.json   （只读 frontmatter，毫秒级）
                                                        │
                          lib/postIndex.ts（进程内缓存）◀┘
                          isKnownSlug() / isPrivateSlug() / getPublicSlugs()
```

兜底：清单文件缺失时退化为"只切 frontmatter 文本"的轻量解析（仍然不碰正文、不做加密），并打一条警告。
`npm run predev` 同样会生成它，本地 `next dev` 不会缺文件。

## 七、真实 IP：XFF 的**末段**才可信

```
usertools/nginx-blog.conf:
    proxy_set_header X-Real-IP        $remote_addr;              ← nginx 覆盖写，客户端伪造不了
    proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for; ← **追加**语义
```

`$proxy_add_x_forwarded_for` = 「客户端自带的 XFF」+「nginx 追加的 `$remote_addr`」，
所以**首段完全是访客自己填的**：`curl -H "X-Forwarded-For: $RANDOM"` 就能把自己伪装成无数新访客，
把 UV 和"第 N 位访客"直接刷上天。**末段才是可信的那个**。

`lib/analytics.ts` 的 `clientIp()` 因此实现为：只信 `X-Real-IP`；没有它时取 XFF 的**最后一段**。
如果站点前面还有 CDN，这里的口径要跟着改（CDN 回源地址会变成对端地址）。

## 八、nginx 限流

`usertools/nginx-blog.conf` 顶层加了 `limit_req_zone $binary_remote_addr zone=blog_api:10m rate=120r/m;`
——该文件整个被 include 进 `http` 上下文，所以 `limit_req_zone` 能直接写在文件顶层，不必另开 `conf.d/` 文件（少一份"双份不同步"的风险）。

两个 `location =` 精确匹配 `/api/stats`、`/api/like`，`burst` 分别 40 / 20、`nodelay`，超限回 **429**（不是默认的 503）。

⚠️ **不要图省事写成 `location ^~ /api/`**：`/api/view`、`/api/download` 会被 pdf.js 用**大量 Range 请求**打，
限流会直接把手机端的 PDF 阅读打断。

## 九、私有内容的默认口径

- **私有文章**：详情页的互动条放在 `PrivateGate` 的 children 里 → **锁着时连按钮节点都不存在**，解锁后才出现；
- 列表卡片上不露出私有文章的赞数（`REACTIONS.exposePrivateOnCards = false`，改 `lib/site.ts` 一处即可翻转）；
- 私有文章的**浏览量照常记录**（只有站主自己能在库里看），但不进 `GET /api/stats` 的公开 `posts` 映射。

## 十、部署

```powershell
usertools\deploy-code.ps1                  # 代码 + 服务器构建 + pm2 重启（prebuild 会在服务器上生成 data/post-index.json）
usertools\setup-nginx.ps1 -SkipCert        # 只有改了 nginx-blog.conf 才需要；-SkipCert 表示不动证书
```

- `data/` 目录由代码在首次请求时自动创建，**部署脚本不要动它**；
- nginx 那份配置与服务器 `/etc/nginx/sites-available/blog` 是**双份**，必须一起改（`setup-nginx.ps1` 会覆盖）；
- 回滚：删掉 `app/api/stats`、`app/api/like` 即可，前端组件在接口 404/429 时会静默降级（侧边栏显示「旅人簿暂不可用」、卡片不显示赞数），不会白屏。
