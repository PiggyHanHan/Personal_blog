# 文章搜索（关键词 / 标题 / 摘要 / 分类 + 拼音）

> 2026-09-09 实现。相关文件：`lib/search.ts`、`lib/searchIndex.ts`、`components/post/PostSearch.tsx`、`app/posts/page.tsx`。

## 一、需求

1. 关键词搜索（标题 / 标签 / 摘要里出现的内容）
2. 文章名搜索（中文标题，或英文 slug）
3. 文章简述（excerpt）搜索
4. 分类搜索——输入「研究」时列出该分类**全部**文章（分类栏之外的第二入口）
5. 以上都支持**拼音**（全拼 + 首字母）
6. 边输入边在下拉里预览（只显示文章名），**回车**后在整页显示完整结果，卡片样式与分类 tab 一致

## 二、总体思路：构建期拼音索引 + 浏览器端匹配

```
content/posts/*.md
   │  getAllPosts()（lib/posts.ts，构建时）
   ▼
buildSearchDocs(posts)        lib/searchIndex.ts   ← pinyin-pro 只在这里用（服务端）
   │  → SearchDoc[]（含 text/py/init 三份索引）
   ▼
app/posts/page.tsx（静态 ○）→ props 序列化进 HTML
   ▼
<PostSearch docs={...}>       components/post/PostSearch.tsx（"use client"）
   │  searchDocs(docs, query)  lib/search.ts（纯函数，浏览器里跑）
   ▼
下拉预览（前 8 条） / 回车 → 整页结果（.quest-board + QuestCard）
```

**为什么这么分**：

- `/posts` 必须保持静态渲染（○），搜索不能走服务端 `searchParams`（见 AGENTS.md 既定方案 1）。
- `pinyin-pro` 的词典体积不小，**只放在构建期**，浏览器端零依赖、零额外体积（`/posts` 的 First Load JS 仅 +3.65 kB，主要是搜索 UI）。
- `lib/search.ts` 不 import 任何拼音库、不 import `node:fs`，因此服务端建索引与浏览器匹配可以共用同一套打分逻辑。

## 三、索引结构（`SearchDoc`）

每个字段存三份：

| 键 | 含义 | 例（标题「复变函数」） |
| --- | --- | --- |
| `text` | 原文归一化（小写、去空格标点） | `复变函数` |
| `py` | 全拼，**按音节用空格分隔** | `fu bian han shu` |
| `init` | 首字母拼音 | `fbhs` |

字段与权重（`FIELD_WEIGHTS`）：

| 字段 | text | py | init |
| --- | --- | --- | --- |
| title | 100 | 74 | 58 |
| category | 92 | 62 | 46 |
| slug | 64 | — | — |
| tags | 50 | 34 | 28 |
| excerpt | 36 | 24 | 18 |

`slug` 同时索引带连字符与去连字符两种写法（`dsh-config-debugging` / `dshconfigdebugging`），所以 `dsh-config-debugging`、`dshconfig` 都能命中。

## 四、匹配规则（`lib/search.ts`）

- **分词**：按空格切词，每词归一化（ü→v、去声调、全角转半角、小写、去空格标点，只留汉字/字母/数字）。多个词是**与**关系（每个词都要命中某个字段）。
- **打分**：每个词对每个字段的 text/py/init 分别试，取最高分；命中方式有加成——完全相同 +40、前缀 +18、包含 +0。整篇得分＝各词最高分之和，排序按分数降序、同分按日期新者在前。
- **拼音音节边界**：`py` 存的是音节分隔串，全拼命中必须**落在音节边界**上，避免跨音节误命中——标题里的「3D视觉」拼成 `3d shi jue`，输入 `dsh` 不会命中；而 `fubian`（复变）、`hanshu`（函数）、`shijue`（视觉）、`3dshijue` 都正常命中。
- **单字符**：长度 1 的词只做 text 匹配 + 首字母前缀匹配，不做首字母中间匹配（避免 `a` 命中一大片）。
- **分类整体命中**：整词恰好等于某分类的原文或全拼（`研究` / `yanjiu` / `工程` / `gongcheng` / `生活` / `shenghuo`）时，**直接返回该分类全部文章**（`SearchResult.category` 一并返回，结果页显示「分类「研究」」）。首字母形式（`yj`）不做硬过滤，只作为普通高分匹配。
- **变体容错**：`研究文章` 会同时尝试去掉尾部「文章」的形式，和分类 tab 的命名对齐。

## 五、交互（`components/post/PostSearch.tsx`）

- 输入即出下拉（最多 10 条，**一行一条、只显示文章名**，命中处高亮；命中原因（标题/分类/链接/标签/摘要·拼音）放在该行的原生 `title` tooltip 里，不占版面）。
- **回车**：提交搜索，整页显示完整结果（`.quest-board` + `QuestCard`，与分类 tab 完全同一套卡片），并隐藏分类 tab；顶部显示「搜索结果「xxx」· N 篇」和「← 返回分类浏览」按钮。
- **↑/↓** 在下拉里移动高亮，**Esc** 关下拉 / 清空，点击下拉项直接进文章。
- 中文输入法组合期间（`isComposing`）的回车交给输入法，不触发提交。
- 搜索状态只在组件内（不写 URL），因此不引入 `?q=`，避免 `/posts` 与静态导航语义纠缠。

### 两个必须守住的布局细节

1. **下拉条的定位上下文是 `.post-search__field`（只包搜索框和下拉条），不是 `.post-search`**。`.post-search` 里还放着下面的分类 tab 和整列卡片，若把 `position: relative` 放在它上面，下拉条的 `top: 100%` 会按"搜索框 + 所有卡片"的高度计算，被推到页面最底部（表现为"打字没反应"）。改版时别把这两层合并。
2. **下拉条背景要不透明**（`#faf6ec`）。站点卡片用的是半透明 `--paper`，下拉条悬浮在卡片之上时半透明底会让下面的正文透上来，糊成一片。
3. 搜索框上下留白要相等（上方 `.page-stack` 的 gap 1.15rem + `.page-head` 的 0.4rem ≈ 25px，下方 `.post-search__field` 的 1.5rem ≈ 24px），这样它才落在「按时间倒序…」一行与分类标签行之间居中。

## 六、扩展

- **加字段**：在 `SEARCH_FIELDS` 加键 → `FIELD_WEIGHTS` 配权重 → `lib/searchIndex.ts` 的 `buildIndex` 里补该字段的索引 → `lib/site.ts` 的 `POSTS.search.fields` 补中文标签。
- **改文案**：全部在 `lib/site.ts` 的 `POSTS.search`。
- **换分词/拼音库**：只动 `lib/searchIndex.ts` 的 `toPinyin`，匹配逻辑不受影响。

## 七、已知边界

- 拼音匹配基于**预生成的字符串**，所以中英混输（如 `fubian函数`）不命中；纯中文、纯拼音、纯英文、拼音+空格分隔的多词都正常。
- 多音字按 pinyin-pro 的上下文判断（`重庆`→`chongqing`、`银行`→`yinhang`），单字段语境下的判断偶有偏差属正常。
- 文章数量在数百篇以内时，浏览器端全量匹配的开销可忽略；若将来上千篇，再考虑前缀索引或 Web Worker。
