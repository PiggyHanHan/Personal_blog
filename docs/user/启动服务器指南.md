# 启动服务器指南（部署到自己的服务器）

> 本文是**通用模板**。首次使用前，把所有脚本顶部的两个变量改成你自己的：
>
> ```powershell
> $Key    = "C:\Users\<你的用户名>\.ssh\<你的密钥>.pem"   # 你的 SSH 私钥
> $Server = "root@<你的服务器IP>"                        # 你的服务器
> ```
>
> 域名相关（`blog.example.com` 等）同理，在 `usertools/setup-nginx.ps1`、`setup-ssl.ps1`、`nginx-blog.conf` 里全局替换。
>
> 【编码】所有 ps1 必须保存为 **UTF-8 with BOM**（PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文注释会破坏解析）；远程命令串 `$remote` 用**单引号**包住，防止 PowerShell 抢先展开 `$(...)`。`nginx-blog.conf` 相反，必须**不带 BOM**。

## 一、本地跑起来

```powershell
usertools\local-run.ps1            # 本地预览：跳过加密，私有文章明文可见
usertools\local-run.ps1 -Encrypt   # 本地也走加密：浏览器里输口令才能读
```

浏览器开 `http://localhost`（80 端口）能看到博客 = 成功。

## 二、日常部署速查

所有脚本自动切到项目根目录，从任意位置调用都可以。

| 场景 | 脚本 | 说明 |
| --- | --- | --- |
| 本地预览 | `usertools\local-run.ps1` | 构建 + 80 端口起服务 |
| 只改了 `content/` | `usertools\sync-content.ps1` | 镜像 content/ + 重建 + pm2 重启（`-NoBuild` 只传） |
| 改了代码（app/components/lib…） | `usertools\deploy-code.ps1` | 打 light 包上传 + 重建 + 重启 |
| 只换背景图 / 开屏素材 | `usertools\sync-bg.ps1 -File public/bg/新图.jpg` | 只传那张图，不用重建 |
| 全新部署 | `usertools\deploy-fresh.ps1` | 旧目录备份为 `blog_backup_<日期>`，需输入 DEPLOY |
| 改私有文章口令 | `usertools\set-private-password.ps1` | 本地 + 服务器一起改并重建（`-Generate` 生成强口令） |

> ⚠ **代码先行**：`sync-content.ps1` 只镜像 `content/`。如果服务器上还是旧代码（不认 `private: true`），私有文章会被**明文发布**。大改代码后用 `deploy-code.ps1`。

> **互动数据（访客计数 / 点赞 / 表情）**：存在服务器 `/var/www/blog/data/blog.db`（SQLite）。它**不在**任何部署包里，`deploy-code.ps1` 也**不会删**它——代码更新不会丢计数。⚠️ 反过来：**永远不要把 `data/` 加进 `deploy-light.ps1` 白名单**（本地那份是空的，传上去等于清空线上数据）。备份与清零见第六节。

## 三、服务器准备（一次性）

要求：Ubuntu / Debian，**Node.js ≥ 22.13**（互动数据用内置 `node:sqlite`，低于这个版本要加 `--experimental-sqlite`；Node 22.5 以下没有这个模块），Nginx，pm2。

```bash
mkdir -p /var/www/blog
# 上传代码后：
cd /var/www/blog
npm install
npm run build
pm2 start npm --name blog -- start -- -p 3000
pm2 save && pm2 startup
```

## 四、Nginx + HTTPS（一次性）

1. 在 SSL 服务商申请证书，下载 pem/key 放到本地（如 `C:\Users\<你>\.ssh\`）
2. 把 `usertools/setup-nginx.ps1` 与 `usertools/nginx-blog.conf` 里的 `blog.example.com` 全局替换成你的域名
3. 执行：

```powershell
usertools\setup-nginx.ps1 -Cert "C:\Users\<你>\.ssh\blog.example.com.pem" -KeyFile "C:\Users\<你>\.ssh\blog.example.com.key"
```

它会：上传证书到 `/etc/nginx/ssl/`（私钥 600）→ 覆盖站点配置 → `nginx -t` 通过才 reload。续期 / 换证书用 `usertools\setup-ssl.ps1`。

> 域名要先解析到服务器 IP；云服务商安全组放行 80 / 443。裸 IP 刻意不跳 HTTPS（证书 SAN 里没有 IP，一跳必撞证书错误）。

## 五、私有文章口令

- 本地：`.env.local` 里的 `PRIVATE_POST_PASSWORD`（不进 Git）
- 服务器：`/var/www/blog/.env.local` 放同一份（部署脚本不会覆盖它）

服务器上缺这份文件时，含 `private: true` 文章的构建会**直接失败**（刻意防明文泄露）。校验加密链路：

```powershell
node scripts\verify-private-crypto.mjs
```

## 六、互动数据（备份 / 清零）

访客计数、点赞与表情存在服务器 **`/var/www/blog/data/blog.db`**（SQLite，WAL 模式），`data/post-index.json` 是构建期自动生成的文章清单（点赞接口的白名单）。它们都**不参与部署**，也没有对应的 ps1——需要时在服务器上跑几条命令。

下面的命令把 SSH 那两处占位符换成你自己的（与脚本顶部一致）。

### 6.1 备份（**必须连 `-wal` 一起**）

```powershell
# 打包整个 data/ 目录（db + wal + shm 一起，才是完整可恢复的一份）
# ⚠️ 远端命令串用单引号：双引号里的 $(...) 会先被本地 PowerShell 展开，到不了服务器
ssh -i "C:\Users\<你的用户名>\.ssh\<你的密钥>.pem" root@<你的服务器IP> `
  'tar -czf /root/blog-data-$(date +%Y%m%d).tar.gz -C /var/www/blog data && ls -lh /root/blog-data-*.tar.gz | tail -1'
```

⚠️ **只 copy `blog.db` 会拿到空库**：WAL 模式下新写入的行躺在 `blog.db-wal` 里。要单独导出一个干净副本，用 `VACUUM INTO`：

```powershell
ssh -i "C:\Users\<你的用户名>\.ssh\<你的密钥>.pem" root@<你的服务器IP> `
  'node -e "const{DatabaseSync}=require(\"node:sqlite\");new DatabaseSync(\"/var/www/blog/data/blog.db\").exec(\"VACUUM INTO \x27/root/blog-snapshot.db\x27\")" && ls -lh /root/blog-snapshot.db'
```

### 6.2 清零（重置访客数 / 点赞，比如公开发布前清掉测试数据）

⚠️ **清零不可恢复**，建议先按 6.1 备份一次。

```powershell
# 多行远端命令一律用「先赋值给变量，再传变量」——这种写法实测最稳
$clear = @'
node -e "
const {DatabaseSync}=require('node:sqlite');
const db=new DatabaseSync('/var/www/blog/data/blog.db');
db.exec('PRAGMA busy_timeout=8000;');
db.exec('DELETE FROM visits; DELETE FROM reactions;');
db.exec('VACUUM;');
db.exec('PRAGMA wal_checkpoint(TRUNCATE);');
console.log('visits='+db.prepare('select count(*) n from visits').get().n,
            'reactions='+db.prepare('select count(*) n from reactions').get().n);
" 2>&1 | grep -v Experimental | grep -v trace-warnings
'@
ssh -i "C:\Users\<你的用户名>\.ssh\<你的密钥>.pem" root@<你的服务器IP> $clear
```

要点：

- **不用重启 pm2**：清的是表里的行，Next 进程读的是同一个库；清完打开页面会从「第 1 位访客」重新开始。
- **`VACUUM` + `wal_checkpoint(TRUNCATE)` 两句都要**：只 DELETE 的话旧行还会留在 `blog.db-wal` 里。
- `GET /api/stats` **不会**产生访问记录，所以你自己查完仍然是 0（只有真实的页面浏览 `POST` 才计数）。
- 想连匿名盐一起换掉（让旧访客哈希彻底不可关联）：额外加一句 `db.exec('DELETE FROM meta;')`，下次运行会自动生成新盐。

### 6.3 看一眼现在有多少

```powershell
$probe = @'
node -e "
const {DatabaseSync}=require('node:sqlite');
const db=new DatabaseSync('/var/www/blog/data/blog.db');
console.log('visits='+db.prepare('select count(*) n from visits').get().n,
            'reactions='+db.prepare('select count(*) n from reactions').get().n);
" 2>&1 | grep -v Experimental | grep -v trace-warnings
'@
ssh -i "C:\Users\<你的用户名>\.ssh\<你的密钥>.pem" root@<你的服务器IP> $probe
```

或者直接看接口（`GET` 不记数）：浏览器打开 `https://<你的域名>/api/stats`。

> 设计细节（为什么选 `node:sqlite`、真实 IP 怎么取、为什么只给两个接口限流）见 `docs/dev/互动数据.md`。
