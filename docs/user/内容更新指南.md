# 内容更新指南（文章 / 项目 / 友链）

博客的三个内容板块都不需要碰代码，改文件就行：

| 板块 | 改哪个文件 |
|---|---|
| 文章 | `content/posts/*.md` |
| 项目 | `content/projects.json` |
| 友链 | `content/links.json` |

## 改完怎么生效

```
node node_modules\next\dist\bin\next build      # 1. 重新构建
node node_modules\next\dist\bin\next start -p 80  # 2. 重启服务（-p 80 是博客端口，可换）
```

> `content/files/` 下的 PDF 附件例外：只替换同名 PDF 文件不用构建，刷新页面就生效；改了文章正文里的引用才需要重新构建。

## 一、文章

### 新建一篇文章

1. 在 `content/posts/` 下新建 `.md` 文件，**文件名随意（可以用中文）**
2. 文件头写 frontmatter，正文写 Markdown：

```md
---
title: 文章标题
slug: my-post            # 链接 → /posts/my-post（必填英文）
date: 2026-08-11        # YYYY-MM-DD
category: 研究          # 文章分类：研究 | 工程 | 生活（决定文章页落在哪个切换页；缺省为生活）
excerpt: 列表页显示的摘要一句话
tags: [遥感, 计算机视觉]
---

这里是正文……

## 小节标题

第二段内容。
```

**文章分类（`category`）**：`研究`、`工程` 或 `生活`，文章页顶部用切换按钮分成「研究文章 / 工程文章 / 生活文章」三个板块（从左到右），每篇文章按此归入其中。不写默认归入「生活」。研究类通常是论文 / 调研 / 技术方向的思考（常带 `pdf`），工程类是开发实践 / 调试排障 / 工具使用，生活类是笔记 / 随笔 / 反思 / 见闻。

**slug 规则（最重要）**：只能用英文字母 / 数字 / 下划线 / 连字符，不能以符号开头。
- 中文 slug 会导致详情页 404（构建时会报错提醒）
- 中文文件名没问题，只要 frontmatter 里有英文 `slug`

### 正文支持的语法

| 语法 | 写法 |
|---|---|
| 段落 | 直接写文字，空行分段 |
| 二级标题 | `## 标题` |
| 三级标题 | `### 标题` |
| 引用 | `> 引用内容` |
| 列表 | `- 无序` 或 `1. 有序` |
| 代码块 | 三个反引号包裹 |
| 粗体 / 斜体 | `**粗体**` / `*斜体*` |
| 行内代码 | 单个反引号包裹 |
| 链接 | `[文字](https://example.com)` |
| 图片 | 见下方「放图片（文章插图）」 |
| 删除线 | `~~文字~~` |
| 表格 | GFM 表格（竖线分隔），写法见下 |

```md
| 列1 | 列2 |
| --- | --- |
| 内容A | 内容B |
```

暂不支持：原始 HTML（会被当文本转义显示）、嵌套列表（会摊平显示）。

### 放图片（文章插图）

**规则就三条，第一条最重要：**

1. **每张图只用一次**：一张图只属于一篇文章（且只出现一次）。需要重复展示时，把图片**复制一份、换个文件名**再用——不要复用同一文件，否则以后改 / 删这张图会连带影响别处。
2. **原图放 `content/md_images/`**，md 里写相对路径 `../md_images/xxx.png`（不要写 `/md_images/...`，也不要丢进 `public/`）。
3. **构建时自动压缩**：`npm run build` 前会把 `content/md_images/` 的原图等比压缩（最长边 1600px）成**同名文件**放进 `public/md_images/`，网站加载的是压缩图，本地 / GitHub 预览看的是原图。

**为什么写 `../md_images/` 相对路径**：同一路径两处通——

- 本地 / GitHub 预览：从 `content/posts/文章.md` 出发，`../md_images/xxx.png` → `content/md_images/xxx.png`（原图）
- 网站详情页：从 `/posts/xxx` 出发，解析到 `/md_images/xxx.png` → `public/md_images/xxx.png`（压缩图）

**一张图**：

```md
![胡桃](../md_images/hutao.png)
```

**多张图并排**：同一行写多张，自动等宽等高对齐：

```md
![a](../md_images/a.png) ![b](../md_images/b.png)
```

**矩阵（多行多列）**：每行图片写在一行里，行与行之间**空行分隔**（或行尾两个空格硬换行）——连续图片行自动合成网格，同行上下对齐、同列左右对齐：

```md
![a](../md_images/a.png) ![b](../md_images/b.png)

![c](../md_images/c.png) ![d](../md_images/d.png)
```

> 窄屏（手机）自动变单列竖排。图片等比缩放、自动填满对齐；如果截图边缘被裁掉内容，可以把 `app/blog.css` 里 `.image-grid figure img` 的 `object-fit: cover` 改成 `contain`（不裁切、改为留白）。

### 放 PDF / 附件（学术论文）

1. 把 PDF 放进 `content/files/`（没有就新建），**中文文件名、带标点都可以**
2. 文章 frontmatter 加 `pdf` 字段（指向 PDF 路径），正文正常写摘要 + 下载链接：

```md
---
title: 论文标题
slug: my-paper
date: 2026-08-11
category: 研究
excerpt: 摘要一句话
tags: [遥感, 计算机视觉]
pdf: /files/我的论文.pdf
---

## 论文

这里写摘要和介绍……

[📄 下载《XXX》全文 PDF](/files/我的论文.pdf)
```

效果：
- 加了 `pdf` 字段后，文章页顶部出现**全文预览**区 + **新窗口打开**按钮（走 `/api/view` 接口内联返回，不触发下载）
- **电脑上**：预览区用浏览器原生阅读器内嵌显示，点进文章就能翻页看；点「新窗口打开」会新开标签页显示 PDF
- **手机上**：手机浏览器不支持 iframe 内嵌 PDF，预览区改用 **pdf.js 在页面内渲染**（canvas 画出来），小米、微信等国产浏览器也能直接翻页看；首次打开要等几秒（文档解析 + 渲染）
- 预览区**没有下载按钮**——下载入口就是正文里的链接，正文里指向 `/files/*.pdf` 的链接点一下即可下载/打开文件
- 访问地址 = `/files/` + 文件名

### 改文章 / 删文章

- 改：直接编辑对应 `.md` 文件，重新构建
- 删：删掉文件，重新构建

## 二、项目

文件：`content/projects.json`，整体结构：

```json
{
  "featured": {
    "title": "精选项目",
    "empty": "项目整理中，敬请期待。",
    "projects": [ 项目对象 ]
  },
  "projects": {
    "title": "项目",
    "intro": "学术与个人项目一览。",
    "columns": [
      { "name": "学术项目", "projects": [ 项目对象 ] },
      { "name": "个人项目", "projects": [ 项目对象 ] }
    ]
  }
}
```

> 项目页顶部用**切换按钮**展示这两组（学术项目 / 个人项目），每次显示一组，不是并排两列。

**项目对象**格式：

```json
{
  "name": "项目名",
  "url": "https://github.com/xxx/xxx",
  "desc": "一句话描述",
  "status": "已完成",
  "meaning": "分类说明",
  "priority": "核心"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 项目名 |
| `url` | | 项目链接 |
| `desc` | ✅ | 描述 |
| `status` | | 状态文字（已完成 / 推进中…） |
| `meaning` | | 意义说明 |
| `priority` | | `核心` / `重要` / `次要`，影响卡片样式 |

- `featured.projects` = 首页"精选项目"区块
- `projects.columns` = 项目页顶部的两个切换页（学术项目 / 个人项目）
- 加项目：往对应数组里复制一个对象改内容即可

## 三、友链

文件：`content/links.json`：

```json
{
  "title": "友链",
  "intro": "我的朋友们。",
  "empty": "友链建设中，敬请期待。",
  "links": [
    { "name": "昵称", "url": "https://example.com", "note": "备注", "avatar": "/friends/xxx.png" }
  ]
}
```

- `name`、`url` 必填
- `note`：备注（网站形式等），可省略
- `avatar`：头像路径，可省略（没有时显示首字母）

---

## 四、JSON 注意（项目 / 友链）

- 字段名和字符串用**双引号**
- 不能写注释
- 数组最后一个元素后面**不能有多余逗号**
- 写坏了会回退成空数据，构建时终端会打印 `[content] 解析 xxx.json 失败` 的报错提示
