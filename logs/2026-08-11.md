## 修复：文章页切换卡顿 + 开屏重播

用户反馈：导航切其他页面很快，切到文章有延迟；第一次切到文章甚至重播完整开屏。

**根因排查**（Playwright 实测 + build 输出对比）：
1. `app/posts/page.tsx` 服务端读取 `searchParams` → `/posts` 被标记为**动态渲染（ƒ）**，其余页面全是静态（○）。隧道访问下每次导航都要服务端实时渲染 RSC，比静态页慢；请求失败时 Next.js 还会**降级整页刷新**。
2. `IntroOverlay` 无任何"已看过"持久化 → 任何整页加载（刷新/降级导航）都会重播完整开屏。

**修复**：
- `/posts` 静态化（ƒ → ○）：去掉服务端 searchParams 依赖，`?post=` 返回定位移到客户端——`TabbedSections` 用 `useSearchParams` + 静态 `slugToTabName` 映射（优先级 URL > props），`posts` / `projects` 页都补了 `<Suspense>` 边界（useSearchParams 的静态渲染要求）
- `IntroOverlay` 加会话去重：sessionStorage `blog-intro-seen=1`，同标签页内任何整页加载不再重播开屏，新开标签页/新会话才正常重播

**验证**：build 通过（/posts 变 ○）；Playwright 实测切换耗时 118ms → 47ms；整页刷新不重播开屏、新标签页正常重播；`/posts?post=xxx` 返回定位 tab 正确。

## 修复 08-10 日志混合编码

- `logs/2026-08-10.md` 是混合编码：**前段 UTF-8 + 后段 GBK**（同一文件两种编码），编辑器按 UTF-8 打开时后半部分乱码
- 修复：从 git HEAD 取回原始字节，逐行识别 UTF-8 / GBK 统一转码为 UTF-8，171 行 UTF-8 + 115 行 GBK，0 丢失
- 教训：处理乱码文件前先做字节级诊断（`git show HEAD:文件` 对比），不要用 `errors="replace"` 读回写（会把无法解码的 GBK 字节永久替换成 U+FFFD）

## 补充：日志编码修复过程踩的坑（自查）

- 第一版修复脚本用 UTF-8 + `errors="replace"` 读文件 → 后段 GBK 字节全部变成 U+FFFD 写回，**原始字节被永久破坏**（幸好 HEAD 里还有原始版本）
- 正确做法：从 git 取原始字节，逐行尝试 `decode('utf-8')` → 失败再 `decode('gbk')`，统一写回 UTF-8
- 另注意：PowerShell 控制台按 GBK 显示 UTF-8 输出，看中文结果必须用文件/断言（True/False），不能直接读终端
