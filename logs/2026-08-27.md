### 1.2 SSH 连接问题

**问题1：pem 文件权限太开放**

```
Permissions for 'PiggyHanHan.pem' are too open.
It is required that your private key files are NOT accessible by others.
```

Windows 默认给所有用户读取权限，SSH 拒绝使用。

**修复**：
```powershell
icacls "PiggyHanHan.pem" /inheritance:r /grant:r "28646:F" "NT AUTHORITY\SYSTEM:F"
```
只保留当前用户和 SYSTEM 完全控制。

**问题2：复制文件权限被拒**

修改权限后，原路径的文件无法复制（权限被锁）。解决：给当前用户加回读取权限后复制，再对副本重新设权限。

### 1.3 安装 Node.js

- 首次安装 Node.js 18（nodesource 默认）
- 构建时报错：`sharp` 模块要求 Node.js >= 20.9.0
- 升级到 Node.js 22（当前稳定版），重新 `npm install`，构建成功

**教训**：`sharp@0.35.3` 和 `pdfjs-dist@6.2.108` 都要求高版本 Node.js，服务器必须用 22+。

### 1.4 安装 PM2 和 Nginx

```bash

apt install -y nginx
```

PM2 配置开机自启：
```bash

```

## 第二轮：项目上传与构建

### 2.1 打包策略

**问题**：最初用 `tar --exclude` 排除不需要的目录。用户指出：如果以后新增文件夹，exclude 列表不会自动更新。

**解决**：改用**明确包含**方式——`deploy-pack.ps1` 脚本直接列出需要打包的文件/目录，新增文件只需在脚本里加一行。

**打包清单**：
- 代码：app/, components/, lib/, scripts/, types/
- 内容：content/, docs/
- 静态资源：public/files/, public/friends/（bg/ 和 hutao/ 单独上传，文件较大）
- 配置：package.json, next.config.ts, tsconfig.json 等

### 2.2 上传与构建

```powershell
# 本地打包
.\deploy-pack.ps1

# 上传到服务器
scp -i "...\PiggyHanHan.pem" blog.tar.gz root@114.215.204.241:/var/www/blog.tar.gz
scp -r -i "...\PiggyHanHan.pem" public\bg root@114.215.204.241:/var/www/blog/public/
scp -r -i "...\PiggyHanHan.pem" public\hutao root@114.215.204.241:/var/www/blog/public/

# 服务器上构建
ssh -i "...\PiggyHanHan.pem" root@114.215.204.241
cd /var/www/blog && tar -xzf blog.tar.gz && rm blog.tar.gz
npm install && npm run build
pm2 start npm --name blog -- start -- -p 3000
pm2 save
```

构建成功，22 个静态页面全部生成。

### 2.3 Nginx 反向代理

**问题**：PowerShell 的 `$` 变量在 SSH heredoc 中被解释，导致配置文件内容被破坏。

**解决**：在本地写好配置文件，再 `scp` 上传到服务器。

```nginx
server {
    listen 80;
    server_name _;
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

## 第三轮：安全组与验证

### 3.1 安全组端口

服务器本地 `curl localhost:3000` 返回 200，但公网访问超时。

**原因**：阿里云安全组默认只开放 22 端口（SSH），80 端口未放行。

**解决**：在阿里云控制台 → 安全组 → 入方向 → 添加 TCP 80 端口规则（0.0.0.0/0）。

### 3.2 验证成功

浏览器打开 `http://114.215.204.241`，博客正常显示。

## 教训小结

- Windows 上 pem 密钥文件权限默认太开放，需要 `icacls` 收窄到只允许当前用户。
- `sharp` 等原生模块对 Node.js 版本有硬要求，服务器 Node.js 版本不能太旧。
- PowerShell 的 `$` 变量会在 SSH heredoc 中被解释，写配置文件要用本地写好再 scp 上传。
- 阿里云安全组默认只开 22，80 端口需要手动添加入方向规则。
- 打包用"明确包含"比"排除"更灵活，新增文件夹不需要改 exclude 列表。
