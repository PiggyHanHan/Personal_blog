# 2026-08-13 日志

## 第一轮：图片不显示（路径问题）

**现象**：`content/posts/DeepSeek Harness 初体验.md` 里两张截图不显示。

**根因**：md 里写的是 `../../public/md_images/xxx.png`。Next.js 把 `public/` 目录映射到**网站根路径**，文件实际地址是 `/md_images/xxx.png`（不是 `/public/md_images/...`）；从详情页 `/posts/slug` 相对解析 `../../public/...` 得到 `/public/md_images/...` → 404。

**修复**：改为根绝对路径 `/md_images/xxx.png`。

## 第二轮：并排布局（imageRow）——两轮排查才定位真因

**需求**：两张图横着放。

**实现**：`paragraphToBlocks` 把「同一行多张图」解析成 `imageRow` 块，PostBody 渲染 flex 行（各 45% 宽）；md 把两张图写到同一行。

**用户构建后仍竖排**，排查过程：
1. 先怀疑 `.next` 残留旧构建：查 `BUILD_ID` 时间戳（0:15:53 晚于源码 0:12:xx）、grep `.next/server` 产物里的 `imageRow`（chunk 545.js 确实有新代码）、80 端口进程启动时间（0:16:00 晚于构建）——**构建本身是新的**。
2. 抓线上 HTML：图片渲染成**不带 figure 的裸内联 `<img>`**（旧解析器行为）。
3. 决定性一步：把 `lib/markdown.tsx` 转译成 CJS、用**真实解析器 + 真实 md 文件**跑最小复现，dump mdast 树——**remark-parse 会在行内相邻图片之间插入一个空白 text 节点**：`children = [image, text(" "), image]`。我写的判断 `images.length === node.children.length`（2 === 3）不成立 → 整段降级为普通段落 → 图片退化成内联 `<img>`。

**修复**：先剔除纯空白 text 节点再判断是否全是图片。

> 教训：服务端渲染结果反常时，先怀疑解析逻辑本身，用真实输入做最小复现，比翻构建缓存高效得多。

## 第三轮：表格显示为原始文本（GFM 支持）

**现象**：「关键指标对比」表格原样输出 `| 指标 | ... |`。

**根因**：解析器只有 `remark-parse`（CommonMark），**不支持 GFM 表格扩展**。

**修复**：
- 装 `remark-gfm@4.0.1`。npm 缓存目录 `E:\nodejs_cache\_cacache` 在沙箱外被拒（EPERM），用 `npm.cmd install remark-gfm --cache .npm-tmp-cache` 把缓存指到工作区解决。
- 解析器 `.use(remarkGfm)`；`nodeToBlocks` 新增 `table` 节点 → `table` 块（首行作表头、保留 `align`）；PostBody 渲染 `<table>`（thead/tbody、按列对齐）；blog.css 表格样式（金色描边 + 表头底色 + 斑马纹）。
- 附带收益：remark-gfm 激活了**删除线 `~~`**（渲染器原本就有 `delete` 分支，之前永远解析不到）和裸链接自动识别。

## 第四、五轮：压缩管线 + 矩阵网格（核心机制）

用户方案：**原图放 `content/md_images`，md 写相对路径 `../md_images/xxx.png`（本地/网站同一路径），构建时压缩同名文件到 `public/md_images`**，且明确「以后都这么处理」。

### 压缩管线

- `scripts/compress-md-images.mjs`：用 **sharp**（已在 node_modules——Next 的可选依赖；显式声明进 dependencies）：
  - 等比缩放 `fit: inside` + `withoutEnlargement`，最长边 1600px
  - png：`palette: true`（pngquant 量化）+ 最高压缩等级——实测两张截图 **37KB → 13.6KB（-63%）**
  - jpg/mozjpeg、webp 走质量 82；gif 原样拷贝（避免 sharp 丢帧）
  - mtime 比较跳过未变更文件（幂等）；public 里残留的旧文件自动删除
- `package.json` 加 `prebuild: node scripts/compress-md-images.mjs`——`npm.cmd run build` 前自动执行。
- 现有两张图从 `public/md_images` 移到 `content/md_images`；md 路径改为 `../md_images/...`。

### 路径一致性原理（本地/网站同一路径）

- 本地/GitHub：`content/posts/文章.md` 里 `../md_images/x.png` → `content/md_images/x.png`（原图）
- 网站：`/posts/slug` 页 `../md_images/x.png` → `/md_images/x.png` → `public/md_images/x.png`（压缩图）

### 矩阵网格（imageGrid）

- 新增 `imageGrid` 块（`rows: PostImage[][]`）；`mergeImageRuns` 把**连续**的图片段合并成网格（有文字段落隔开就拆成独立网格）。
- CSS Grid：`grid-template-columns: repeat(var(--grid-cols), 1fr)`（列数 = 最长行图片数）+ 单元格拉伸 + `object-fit: cover` → **同行等高（上下对齐）、同列等宽（左右对齐）、等比不拉伸**；`--grid-cols` 用 CSS 变量，移动端媒体查询强制 1 列。
- **矩阵坑**：连续两行图片**中间没有空行时 remark 合并成一个段落**（软换行）→ 2×2 变 1 行 4 图。修复：`paragraphToBlocks` 按 **break 节点（行尾两个空格硬换行）** 把段内图片拆成多行；空行分段的多段落交给 `mergeImageRuns` 合并。两种写法都支持：空行分隔 / 行尾两空格。
- 图片尺寸实测：dsh 569×331（1.719）、reasonix 574×297（1.933）——**比例不同**，cover 会轻微裁切；若截图边缘内容被裁，改 `contain`（一行 CSS）。
- 验证：矩阵 1×2 / 2×2（两种写法）/ 2×1 竖排 / 参差 2+3 / 文字隔开独立网格，全部通过。

### 其他坑

- **`.gitignore` 是 GBK 编码**（read 工具报 invalid UTF-8）：追加规则必须用 `Encoding.GetEncoding(936)` 读写，别用 UTF-8 工具改（会毁掉原中文注释）。已追加 `/public/md_images/`（压缩产物不入库）。
- **curl 请求中文 URL 要百分号编码**：`/md_images/dsh使用情况.png` 直接 curl 返回 404（原始 UTF-8 字节），编码后 200——浏览器会自动编码，真实用户不受影响。
- **一图一用规则**：用户提到「一个图用多次但不打算改」——写入 `docs/user/内容更新指南.md`：每张图只用一次，复用就复制重命名。

## 全天教训小结

- Next.js `public/` 里的文件映射到网站根路径，md 里引用要用 `/xxx.png`（或相对路径）而不是 `/public/xxx.png`。
- remark-parse 会在行内相邻图片间插入空白 text 节点；判断「整段都是图片」前先剔除纯空白文本。
- remark-parse 默认不支持 GFM 表格 / 删除线 / 裸链接，要 `.use(remarkGfm)`。
- 连续两行无空行 = 同一个段落（软换行）；「按行拆结构」要靠 break 节点或空行分段。
- 沙箱环境里 npm 缓存目录可能在沙箱外 → `--cache` 指到工作区；构建 spawn 被拒则让用户自己跑。
- 非 UTF-8 文件（GBK 等）改动前先确认编码，用对应 code page 读写。
- 服务端渲染 HTML 结构反常 → 直接用解析器跑真实输入做最小复现。
